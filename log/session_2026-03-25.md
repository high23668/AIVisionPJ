## 2. 発生した問題と解決策

### 問題1: GLBファイルを開けない

- `xdg-open sf3d_rgb.glb` → `No application is registered`
- **解決**: trimeshでPLY変換 → meshlabで確認

```bash
python -c "
import trimesh
scene = trimesh.load('results/image_to_3d/sf3d_cup.glb')
m = trimesh.util.concatenate(scene.dump())
m.export('results/image_to_3d/sf3d_cup.ply')
print('頂点数:', len(m.vertices), '/ 面数:', len(m.faces))
"
meshlab results/image_to_3d/sf3d_cup.ply
```

※ `trimesh.load()` が `Scene` オブジェクトを返す場合は `scene.dump()` + `concatenate` が必要

### 問題2: 縦長に歪んだメッシュ

- `data/cup.png` が 2816×1536（横長）→ SF3Dが512×512に強制リサイズ → アスペクト比崩壊
- **解決**: `sf3d_demo.py` に `crop_to_square()` 関数を追加

```python
def crop_to_square(image: Image.Image) -> Image.Image:
    """アルファチャンネルのbboxを中心に10%余白付き正方形クロップ"""
    bbox = image.getbbox()
    # ... (オブジェクト中心で正方形クロップ)
```

- 背景除去後に `crop_to_square()` を適用してからモデルに渡す
- 修正後: カップらしい形状のメッシュが生成された ✓

### 問題3: rembg が手も含めてセグメント

- `data/realsense/rgb.png`（手でカップを持った写真）→ 手もメッシュに含まれた
- **解決**: カップ単体の写真 `data/cup.png` を使用
- 根本解決: Any6D統合時はSAM2でカップだけマスクして渡す
