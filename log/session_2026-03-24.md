## 1. Any6D 技術調査

### 概要
- **論文**: arXiv:2503.18673 (CVPR 2025)
- **著者**: Taeyeop Lee (KAIST) + Bowen Wen (NVIDIA, FoundationPose著者)
- **GitHub**: https://github.com/taeyeopl/Any6D

### コアアイデア
FoundationPose model-freeの最大の弱点「参照画像の既知カメラポーズが必須」を、**InstantMeshによる単一RGB画像からの完全3Dメッシュ生成**で回避。

#### 従来手法の問題
- FoundationPose model-free: 参照複数画像 + 既知カメラポーズ + NeRF学習が必要
- 部分マッチング (部分観測 vs 部分観測) → 非重複視点・オクルージョン時に破綻

#### Any6Dの解決策
「**full-to-partial マッチング**」= 完全3D形状を生成してから部分観測にマッチング

### パイプライン

```
アンカー (RGB-D 1枚)
  ├─ SAM2 → マスク
  └─ InstantMesh → 完全3Dメッシュ (正規化スケール)
                      ↓
            Coarse Alignment (OBBでメトリックスケール推定)
                      ↓
            Fine Alignment (FoundationPose refinementループ
                            + スケール変動サンプリング追加)
                      ↓
            メトリックスケールメッシュ + アンカーポーズ

照会画像 (RGB-D)
  └─ FoundationPose (上のメッシュ使用) → 照会ポーズ

相対ポーズ = アンカーポーズ⁻¹ × 照会ポーズ
```

### 使用ファンデーションモデル

| コンポーネント | 役割 |
|---|---|
| SAM2 (hiera_large) | アンカー画像のセグメンテーション |
| Zero123Plus v1.2 | 単一→6視点マルチビュー画像生成 |
| InstantMesh-Large | 6視点→完全3Dメッシュ生成 |
| FoundationPose | ポーズ仮説生成・精密化・選択 |

### 性能 (HO3D データセット)

| 手法 | ADD-S |
|------|-------|
| 既存最強 (Gedi) | 71.9% |
| **Any6D** | **98.7%** |

### 重要な技術的知見
- **スケール推定がボトルネック**: スケール推定なし→ADD-S 0%、あり→98%
- コンポーネントは**逐次ロード** (del + empty_cache) のため同時に全モデルを保持しない
- Any6D自体の独自学習はなし。事前学習済みモデルの組み合わせ

## 2. VRAM 問題の調査

### 環境
- GPU: Quadro RTX 5000 Max-Q (16GB VRAM)

### コンポーネント別ピークVRAM (逐次実行)

| ステージ | ピークVRAM | 実行後 |
|---------|-----------|--------|
| SAM2-Large | ~1.5GB | 解放 |
| Zero123Plus v1.2 | ~5〜6GB | 解放 |
| **InstantMesh-Large** | **~15〜17GB** | 解放 ← 問題 |
| InstantMesh-Base | ~8〜10GB | 解放 ← Baseなら通過 |
| FoundationPose | ~2〜3GB | 常駐 |

### 対処法 (検討済み)

1. **InstantMesh-Base に変更** (config 1行変更) → T4 16GB での動作実績あり
2. **SAM2-Small に変更** → ~700MB節約
3. **`--img_to_3d` なし** → InstantMesh/Zero123Plusをスキップ、~3〜4GBのみ
4. **クラウドGPU** → Vast.ai RTX 3090 (24GB) ~$0.25/時

## 3. Image-to-3D モデル比較調査

### TripoSR
- 開発: Stability AI + Tripo AI (2024年3月)
- アーキテクチャ: シングルビューLRM
- 弱点: 背面ジオメトリ劣化 (1枚から想像で補完)
- VRAM: ~4GB / 速度: 0.3秒

### InstantMesh
- 開発: Tencent ARC (2024年4月)
- アーキテクチャ: Zero123++ (多視点生成) + スパースビューLRM の2段階
- 強み: 6視点で全周ジオメトリが安定
- VRAM: Base ~10GB / Large ~16〜24GB / 速度: ~25〜35秒

### SF3D (Stable Fast 3D)
- 開発: Stability AI (2024年8月, TripoSRの後継)
- アーキテクチャ: シングルビューだがトリプレーン解像度6倍 (64→384) + DMTet
- **VRAM: ~6GB / 速度: 0.5秒**
- ライセンス: Stability AI Community License (年収$100万以下研究用途は無償)

### ベンチマーク比較 (GSO データセット)

| 手法 | Chamfer Distance ↓ | PSNR ↑ | VRAM | 速度 |
|------|---------------------|--------|------|------|
| **SF3D** | **0.098** | **21.25** | **~6GB** | **0.5秒** |
| TripoSR | 0.111 | 16.45 | ~4GB | 0.3秒 |
| InstantMesh | 0.138 | 15.43 | ~10〜24GB | ~25〜35秒 |

**→ SF3DはInstantMesh-Largeより高精度かつVRAM1/4・速度65倍**

## 4. 方針決定

### Any6D + SF3D 統合アプローチ

Any6DのImage-to-3DモジュールをInstantMeshからSF3Dに差し替える。

#### 技術的変更点
- `sam2_instantmesh.py` の InstantMesh 呼び出し部分を SF3D に置換
- SF3DのGLB出力 → trimesh で OBJ に変換してFoundationPoseパイプラインへ渡す
- SAM2は `-small` モデルに変更 (VRAM節約)

#### 実施フェーズ

```
Phase 1: TripoSR でパイプライン動作確認
         - MIT ライセンス・最シンプル・6GB
         - Any6D全体が正しく動くか確認

Phase 2: SF3D に差し替えて精度検証
         - 幾何精度最高・6GB・0.5秒
         - TripoSRとの精度差を確認

Phase 3 (必要なら): クラウドGPUで InstantMesh-Large と比較
         - Vast.ai RTX 3090 ~$0.25/時
         - 論文の公式構成との差を定量評価
```

#### 期待効果
- VRAMピーク: 16〜24GB → **6GB** (大幅改善)
- 推論速度: ~35秒 → **0.5秒** (65倍高速化)
- 幾何精度: CD 0.138 → **0.098** (向上)
