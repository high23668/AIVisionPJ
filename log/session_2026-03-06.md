## 発見したトラブルと解決策

### 1. マスクshapeの不一致 (IndexError)
- **原因**: SAM3の出力マスクが `(1, H, W)` で来るが `(H, W)` を期待していた
- **解決**: `mask.cpu().numpy().squeeze().astype(bool)` で squeeze を追加
- **修正ファイル**: `models/sam3/sam3_demo.py` の `draw_masks()`

### 2. cv2.imshow のセグメンテーションフォルト
- **原因**: CUDA推論後にQt/CUDAのメモリ競合が発生
  - `DISPLAY` 環境変数が VSCode ターミナルに渡されていなかった (空)
  - `DISPLAY=:0` を指定しても cv2.imshow がクラッシュ (PyTorch CUDA使用後)
- **解決**: `cv2.imshow` を廃止し `subprocess.Popen(["xdg-open", out_path])` でシステムビューアを起動
- **修正ファイル**: `models/sam3/sam3_demo.py` の `task_image()`, `task_camera()`, `task_live()`

### 3. task_live のアーキテクチャ変更
- **旧**: cv2.imshow によるライブプレビュー → Enterで撮影
- **新**: テキスト入力 → 撮影 → xdg-openで結果表示 (クラッシュ回避)

## 重要コマンド集

```bash
# SAM3仮想環境アクティベート
source /home/vr01/AIVisionPJ/.venv_sam3/bin/activate

# SAM3 静止画テスト
DISPLAY=:0 python models/sam3/sam3_demo.py --task image \
  --image models/sam3/assets/images/truck.jpg --prompt "truck"

# SAM3 カメラ1枚撮影
DISPLAY=:0 python models/sam3/sam3_demo.py --task camera \
  --source 4 --prompt "cup"

# SAM3 ライブモード (プロンプト入力 → 撮影 → 表示)
DISPLAY=:0 python models/sam3/sam3_demo.py --task live --source 4

# SAM3 ストリーミングモード → ブラウザで http://localhost:8080
DISPLAY=:0 python models/sam3/sam3_demo.py --task stream \
  --source 4 --prompt "cup"
```
