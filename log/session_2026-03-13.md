- 円柱 mesh: サイズ推定が不正確でより悪化
- **根本的問題**: model-free モードは「参照画像の既知カメラポーズ」が必須と判明

## 技術的知見

### FoundationPose model-free モードの真実
- 公式の model-free は BundleSDF でカメラポーズ復元 → NeRF 学習 → FP実行 という3段階
- 参照画像のポーズなしで直接使う方法は**存在しない**
- Isaac ROS 公式も model-free 非対応 (Issue #46)
- Kaolin + PyTorch3D の追加依存が必要で環境構築も困難

### FoundationPose データ形式 (YcbineoatReader)
- `rgb/*.png`: カラー画像
- `depth/*.png`: uint16 PNG (mm単位, FPが /1000 して meters に変換)
- `masks/*.png`: バイナリマスク
- `cam_K.txt`: 3x3 内部パラメータ行列 (スペース区切り)

### RealSense 深度 PNG の表示
- uint16 PNG は標準ビューアで真っ黒に見える (最大値1660 / 65535 = 2.5%)
- データは正常: `cv2.imread(path, -1)` で正しく読める

## 今後の方針

### FoundationPose model-based (推奨)
1. フォトグラメトリ (PolyCam等) で対象物体のメッシュを生成
2. `data/cad_models/object.obj` に配置
3. `fp_create_mesh_and_run.py --mesh_path data/cad_models/object.obj` で実行

### Any6D (CVPR 2025, 将来有望)
- FoundationPose著者 Bowen Wen の後継研究
- RGBD 1枚のみ・カメラポーズ不要・CADメッシュ不要
- GitHub: https://github.com/taeyeopl/Any6D
- セットアップと評価が今後のタスク

## コマンドリファレンス

```bash
# RealSenseキャプチャ
source .venv/bin/activate
python scripts/capture_realsense.py
python scripts/capture_ref_images.py --output data/realsense/ref --n 15

# SAM3マスク生成
source .venv_sam3/bin/activate
python scripts/generate_sam3_mask.py --image data/realsense/rgb.png --prompt "cup"
python scripts/generate_sam3_mask.py --dir data/realsense/ref --prompt "cup"

# FoundationPoseシーン整理
source .venv/bin/activate
python scripts/setup_fp_scene.py

# Dockerコンテナ起動
docker start foundationpose_build

# FoundationPose実行 (CADメッシュあり)
docker exec -it foundationpose_build bash -c '
  source /opt/conda/etc/profile.d/conda.sh && conda activate my &&
  export LD_LIBRARY_PATH=/opt/conda/envs/my/lib/python3.8/site-packages/torch/lib:$LD_LIBRARY_PATH &&
  cd /home/vr01/AIVisionPJ &&
  python scripts/fp_create_mesh_and_run.py \
    --scene_dir data/fp_scene \
    --mesh_path data/cad_models/object.obj \
    --debug_dir results/fp_debug
'
```
